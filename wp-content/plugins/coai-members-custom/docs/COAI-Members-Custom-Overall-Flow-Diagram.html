COAI Members Custom — Overall Diagram-Style Flow Chart

This is the “big picture” of how login/auth → role mapping → staff pages → FluentCRM kiosk/2FA → member directory/edit all connect. It’s intentionally written to help you spot where a redirect or role decision could be coming from.

Doc Type: Overall Flow Diagram Generated: 2026-01-12 Format: HTML (diagram grid + ASCII flow)
Touchpoint Expected behavior Overlap / “two ways to do it” High-risk / “magic likely lives here”
How to use this: When something redirects unexpectedly, find the page you were trying to reach (right side) and trace backwards: kiosk → login_redirect → login-form redirect_to → auth-bridge role map.
1) Entry / Front-End Pages

/member-login/

Front-end login form (shortcode). Honors redirect_to if present.

login-form.php wp_signon()

/member-portal/

Main landing area after login for typical members/staff.

member-portal.php

/staff-newsletters/

Newsletter Center (front-end). Builds FluentCRM links with coai_route.

staff-newsletters.php identity logic

/member-directory/

Directory list + filters + CSV export (template_redirect export).

admin-members.php filters: is_new_member

/member-edit/

“Edit member” front-end view (admin mode uses edit view; member mode likely elsewhere).

admin-members.php wpdb->update()
2) Authentication + Role Mapping

WP Core Auth

If WP username/password matches, it wins first (no wp_members lookup).

wp_authenticate_username_password

COAI Auth Bridge

Fallback auth against wp_members if WP auth fails. Creates/links WP user and sets role.

coai-auth-bridge.php role map: usergroup→role blocks WP-only accounts

Newsletter Manager Role

Creates newsletter_manager WP role (WP-only identity).

coai-newsletter-manager.php add_role()

Identity Helpers (Kiosk)

coai_is_real_admin / coai_is_manager_user / coai_is_newsletter_user

coai-manager-fluentcrm-kiosk.php admins treated as newsletter_user
3) Login Redirect + Guard Rails

Login Redirect Guard

Ensures wp-admin requests go to wp-admin; manage_options users go to dashboard.

coai-login-redirect-guard.php honors /wp-admin

Front-End Login Redirect

login-form.php redirects logged-in users to portal (unless in editing context).

login-form.php can feel “forceful”

Staff Permission Helper

coai_staff_can() gates directory + export + staff shortcut pages.

fallback exists duplication risk
4) FluentCRM Access + Kiosk + 2FA

Newsletter Center Links

Builds FluentCRM entry URLs using admin.php?page=fluentcrm-admin&coai_route=…

staff-newsletters.php coai_route param

Kiosk: Deny Others

Only Manager + Newsletter Manager allowed into FluentCRM pages (non-admin).

kiosk step 1 admin_init very early

Kiosk: Keep Out of wp-admin

Managers/newsletter_manager redirected away from wp-admin pages except FluentCRM/profile/logout/plumbing.

kiosk step 2 can “mysteriously” reroute

Require 2FA Config Before FluentCRM

If WP2FA not configured, redirect to profile.php?page=wp-2fa-setup.

kiosk step 3 reads user_meta keys

coai_route → Hash Route

Converts coai_route=campaigns|broadcasts into FluentCRM hash (footer script).

kiosk step 6 admin_footer script
5) Member Data / Directory / Editing

Directory Filters

Single source: coai_md_build_filters(). New-only = is_new_member=1 only.

admin-members.php filters + join levels

CSV Export

Same filters used; requires nonce; requires coai_staff_can('view').

template_redirect export

Edit View (Staff)

Admin/Manager only. Updates columns after filtering against real DB columns.

wpdb->update() COAI_number casing/guards

COAI # Rules

Uniqueness enforced; “xx” requires TEST- prefix; blank/unchanged not written.

guarded update

Trace Flow (ASCII version)

User hits /staff-newsletters/ ├─ if not logged in → /member-login/?redirect_to=/staff-newsletters/ └─ if logged in: ├─ identity computed (admin | manager | newsletter_manager) ├─ deny if not staff/newsletter └─ clicks Open Campaigns/Broadcasts └─ goes to /wp-admin/admin.php?page=fluentcrm-admin&coai_route=campaigns|broadcasts ├─ coai-login-redirect-guard may influence post-login landing if wp-login involved └─ coai-manager-fluentcrm-kiosk (admin_init) ├─ step 1: deny FluentCRM if not manager/newsletter_manager (non-admin) ├─ step 2: keep manager/newsletter_manager out of wp-admin chrome ├─ step 3: if 2FA not configured → profile.php?page=wp-2fa-setup └─ step 6: convert coai_route → FluentCRM hash route Member Directory (/member-directory/) ├─ filters built by coai_md_build_filters() ├─ "New Members only" = wp_members.is_new_member=1 ONLY └─ Export CSV uses same filters + nonce + coai_staff_can('view') Edit Member (/member-edit/?mid=###) ├─ requires coai_staff_can('manage') ├─ POST → sanitize → filter to real DB columns → guards └─ wpdb->update() writes changes
